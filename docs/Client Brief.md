##  CLIENT BRIEF

1. Client Brief
  Project Title: Learner Support Portal
  Project Team: TPC Group 14

  * Client Brief
    * The client requires a web-based Learner Support Portal that will provide learners with a central platform where they can manage their learning activities, monitor their progress, access learning resources and receive support when needed.
    * The current learning process can make it difficult for learners to keep track of their tasks, understand their progress and easily access the resources they need. The proposed system will provide a simple and user-friendly platform that brings these activities together in one place.
    * The system will primarily be used by Learners and Assessors, with an Admin responsible for controlling assessor account registration and system access.

2. Client Requirements
  * The client requires the system to provide the following functionality:
  * Learner Registration
    * Learners must be able to create their own accounts.
    * Learners must provide the required registration information.
    * The system must prevent invalid or incomplete registration.
    * Login and Authentication
    * Learners must be able to log in using their registered credentials.
    * Assessors must be able to log in using credentials provided by the Admin.
    * Users must only be able to access functionality available to their account.

  * Task Management
    * Learners must be able to view their assigned tasks.
    * Learners must be able to create tasks where applicable.
    * Learners must be able to update task information.
    * Learners must be able to delete tasks.
    * The system must request confirmation before a task is deleted.

  * Progress Tracking
    * Learners must be able to see their learning/task progress.
    * Progress must be calculated based on completed tasks.
    * The system must display progress in an understandable way.
    * The system must not use a points-based progress system.
    
  * Learner Support
    * Learners must have access to a support function.
    * Learners should be able to communicate or submit a support request when they require assistance.

  * Search and Filtering
    * Learners and/or Assessors should be able to search for relevant tasks or information.
    * The system should provide filtering functionality to make information easier to find.

  * Learning Resources
    * Learners must be able to access available learning resources.
    * Assessors must be able to manage/add relevant resources for learners.

  * Mini-Game
    * The system should include a simple educational mini-game.
    * The mini-game should provide an engaging way for learners to interact with the system while supporting learning.

  * Assessor Account Control
    * Assessors must be registered by the Admin.
    * Assessors must receive login credentials from the Admin.
    * Assessors must not be required to complete the normal learner registration process.

3. Expected Users
  * User
  * Main Responsibilities

  * Learner
    * Register, log in, manage tasks, monitor progress, access resources, search/filter information, request support and use the mini-game.

  * Assessor
    * Log in using Admin-provided credentials, manage learner-related learning activities/resources and provide learner support.

  * Admin
    * Control system access and create/provision assessor accounts.

4. Expected Outcome
  * The completed system should provide a simple, accessible and organised learner support environment. Learners should be able to manage their learning activities without relying on multiple separate systems, while Assessors should have appropriate tools to support learners.
  * The system should also ensure that access is controlled appropriately, particularly by ensuring that only learners self-register while assessor accounts are controlled by the Admin.     

5. Project Success Criteria
  * The project will be considered successful when:
    * Learners can successfully register and log in.
    * Assessors can log in using credentials provided by the Admin.
    * Learners can manage their tasks.
    * Deleted tasks require confirmation before removal.
    * Learners can view their progress.
    * Learners can access learning resources.
    * Assessors can manage appropriate resources.
    * Learners can access support functionality.
    * Users can search and filter relevant information.
    * The mini-game works correctly.
    * The system is easy to navigate and understand.
    * The implemented functionality meets the agreed user stories and acceptance criteria.   

6. Scope Summary
  * The project will focus on developing the core functionality required for the Learner Support Portal, including authentication, learner registration, assessor access control, task management, progress tracking, support, search/filtering, learning resources and the educational mini-game.
  * Features such as task due dates, task priority, overdue-task functionality and points-based progress are outside the agreed requirements.
